# Bookmark Manager

Лек, преносим графичен мениджър на отметки, за Linux, вдъхновен от **Bookmark Library / Bookmark Manager прозореца на Mozilla Firefox**.

Идеята е проста: отметките да могат да се управляват в самостоятелно приложение, без предварително да се стартира целият браузър.

> **Статус:** portable Linux desktop application  
> **Основен интерфейс:** HTML/CSS/JavaScript  
> **Desktop shell:** GTK3 + WebKit2GTK  
> **Платформа:** Linux x86_64

---

## Защо съществува този проект?

Firefox разполага с много добър интерфейс за управление на отметки, но Bookmark Library не е отделно, самостоятелно приложение. За да редактирате отметки, обикновено първо трябва да стартирате Firefox.

Това има един очевиден недостатък: за проста операция като подреждане, преименуване или редактиране на отметки се стартира целият браузър и всички негови компоненти.

**Bookmark Manager** е създаден с идеята тази част от функционалността да бъде отделена в малко приложение.

Резултатът е самостоятелен, лек и преносим Bookmark Manager, който може да се държи като отделна utility програма.

---

## Основни функции

- Дървовидна структура на папките.
- Папки и подпапки.
- Добавяне, преименуване и изтриване на папки.
- Добавяне, редактиране и изтриване на отметки.
- Drag & Drop на отметки.
- Drag & Drop на папки.
- Пренареждане на папки.
- Преместване на елементи между папки.
- Пускане на елемент върху папка за преместване вътре в нея.
- Търсене в отметките.
- Светла и тъмна тема.
- Импорт на `bookmarks.html`, включително Netscape bookmark format.
- Импорт на JSON.
- Експорт на избрана папка.
- Експорт на цялата структура.
- Проверка на линкове чрез HTTP заявки.
- Запазване на данните локално.
- Запазване на UI състоянието.
- Запазване на профила и browser storage в директорията на приложението.
- Без нужда от инсталация на самото приложение.

## Portable режим

Приложението е замислено като portable.

След разархивиране структурата приблизително изглежда така:

```text
Bookmark_Manager/
├── bookmarks
├── bookmarks.sh
├── index.html
├── icon.png
├── css/
│   └── style.css
├── js/
│   └── bookmarks.js
└── profiles/
    └── window_state.cfg
```

`bookmarks.sh` стартира приложението с относителни пътища.

Той задава:

```text
WEBKIT_USER_DATA_DIR
WEBKIT_CACHE_DIR
```

така че WebKit данните да се пазят в профила на приложението, а не в стандартния потребителски профил на системата.

Това позволява цялата папка да бъде копирана на друго място или на друг компютър.

### Важно за portable режима

Portable означава, че **данните на приложението са преносими**, но не означава, че Linux системните библиотеки са включени в архива.

Изпълнимият файл е динамично свързан със системни библиотеки. Следователно целевата система трябва да разполага със съвместима графична среда и необходимите WebKit/GTK библиотеки.

## Как работи приложението?

Приложението се състои от две основни части.

### 1. HTML/CSS/JavaScript интерфейс

Основният интерфейс е обикновено web приложение:

- `index.html`
- `css/style.css`
- `js/bookmarks.js`

Това означава, че интерфейсът използва стандартни web технологии.

Данните за отметките се съхраняват чрез:

```javascript
localStorage
```

WebView контейнерът предоставя средата, в която този код работи като desktop приложение.

### 2. Native WebView launcher

Файлът:

```text
bookmarks
```

е native Linux executable, който създава прозорец и зарежда HTML интерфейса в WebKit WebView.

Използваните native технологии са:

- GTK3
- WebKit2GTK 4.0
- JavaScriptCore GTK 4.0
- libsoup 2.4
- GLib и стандартните GTK зависимости

Това е причината приложението да изглежда като нормална Linux desktop програма, въпреки че интерфейсът е изграден с HTML/CSS/JavaScript.

## WebView и съвместимост между Linux дистрибуции

Това е най-важната част при разпространението на готовия бинарник.

Приложението **не използва вграден Chromium/Firefox runtime**.

То използва системния **WebKit2GTK**.

Следователно наличието на WebKit2GTK е задължително.

При липсваща библиотека приложението няма да стартира и системата ще покаже грешка от типа:

```text
error while loading shared libraries:
libwebkit2gtk-4.0.so.37:
cannot open shared object file
```

Същото важи и за други native зависимости.

### Debian 12

Разработващата/компилационната среда трябва да бъде посочена точно според реалната машина, на която е компилиран конкретният binary release.

При Debian 12 е особено важно да се провери конкретният бинарник и неговите GLIBC зависимости, защото **GLIBC е част от операционната система и не е portable библиотека, която обичайно се пренася заедно с приложението**.

Проверка:

```bash
ldd ./bookmarks
```

и:

```bash
readelf --version-info ./bookmarks | grep GLIBC
```

В текущия предоставен бинарник се вижда зависимост от:

```text
GLIBC_2.38
```

Затова този конкретен бинарник не трябва да се описва като универсален „Debian 12 binary“, без допълнително потвърждение на build средата.

Ако действително е необходима поддръжка на Debian 12, най-сигурният подход е бинарникът да бъде компилиран в Debian 12 среда или в съвместим по-стар baseline.

---

## Какви зависимости са нужни?

Конкретният binary използва динамични native библиотеки, сред които:

```text
libwebkit2gtk-4.0.so.37
libjavascriptcoregtk-4.0.so.18
libgtk-3.so.0
libsoup-2.4.so.1
libglib-2.0.so.0
libgio-2.0.so.0
libgobject-2.0.so.0
```

и стандартни графични библиотеки от GTK3/WebKit стека.

На различни Linux дистрибуции имената и версиите на пакетите могат да се различават.

Примерно при Debian-базирана система може да се наложи инсталиране на WebKit2GTK/GTK runtime пакетите.

Проверката на конкретната система е най-надеждно да се направи с:

```bash
ldd ./bookmarks
```

Ако има ред:

```text
=> not found
```

липсва съответната runtime библиотека.

## Стартиране

Направете launcher скрипта изпълним:

```bash
chmod +x bookmarks.sh
```

След това:

```bash
./bookmarks.sh
```

Или директно:

```bash
./bookmarks
```

Препоръчителният начин е чрез `bookmarks.sh`, защото той задава правилните относителни директории за профила и cache-а.

```

Примери:

./bookmarks.sh --dark
```

./bookmarks.sh --devtools

## Къде се пазят отметките?

Приложението използва browser storage чрез WebKit.

В portable режима launcher-ът задава:

```text
WEBKIT_USER_DATA_DIR=<application>/profiles/user
WEBKIT_CACHE_DIR=<application>/profiles/user/cache
```

Това е съществена част от portable дизайна.

При преместване на цялата директория е възможно да се пренесе и локално съхраненото съдържание.

**Препоръка:** винаги правете export на отметките преди големи промени или преместване на данните.

## Архивиране

Най-простият backup е копиране на цялата директория на приложението.

Допълнително може да използвате вградените функции:

- Export на текущата папка.
- Export на всички папки.

Това позволява отметките да бъдат архивирани независимо от WebKit profile storage.

## За кого е предназначено?

Проектът е подходящ за хора, които:

- искат малък самостоятелен Bookmark Manager;
- не искат да стартират цял браузър само за управление на отметки;
- предпочитат portable приложения;
- работят с Linux;
- искат отметките им да бъдат достъпни извън браузъра;
- харесват класическия tree/list модел за управление на файлове и отметки.

---

## Какво не е този проект?

Това не е браузър.

Не се опитва да замести Firefox, Chromium или друг браузър.

Не е синхронизация с Firefox Sync.

Не е cloud bookmark service.

Това е локален GUI инструмент за управление на bookmark колекция.

## Известни ограничения

### Linux runtime зависимости

Готовият binary не е напълно статичен. Той разчита на native библиотеки от системата.

Следователно:

> **Portable ≠ напълно независим от Linux системата.**

Приложението може да бъде копирано между машини, но WebKit/GTK/GLIBC съвместимостта на целевата система трябва да бъде проверена.

### Различни WebKit версии

Различните Linux дистрибуции могат да предоставят различни поколения WebKit2GTK.

Ако конкретната система няма необходимия ABI, готовият binary може да не стартира.

### Wayland / X11

GTK/WebKit използват системния графичен backend.

Съвременните Linux системи могат да работят с Wayland, X11 или комбинация от двата.

Съвместимостта зависи от GTK3, WebKit2GTK и наличните backend библиотеки на конкретната система.

## Диагностика

Ако приложението не стартира:

```bash
ldd ./bookmarks
```

Потърсете:

```text
not found
```

Проверете GLIBC:

```bash
readelf --version-info ./bookmarks | grep GLIBC
```

Проверете WebKit:

```bash
ldconfig -p | grep webkit2gtk
```

Проверете GTK:

```bash
ldconfig -p | grep libgtk-3
```

## Развитие

Проектът е умишлено малък.

Той не се нуждае от огромен framework или тежък browser runtime, за да предостави удобен интерфейс.

Основният принцип е:

```text
HTML + CSS + JavaScript
          ↓
     WebKit2GTK
          ↓
        GTK3
          ↓
      Linux desktop
```

Това прави архитектурата сравнително проста и лесна за поддръжка.
