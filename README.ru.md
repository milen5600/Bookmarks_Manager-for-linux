# Bookmark Manager

Лёгкий переносимый графический менеджер закладок для Linux, вдохновлённый окном **Bookmark Library / Bookmark Manager** браузера Mozilla Firefox.

Идея простая: управлять закладками в отдельном приложении, не запуская предварительно весь браузер.

> **Статус:** portable Linux desktop application  
> **Интерфейс:** HTML/CSS/JavaScript  
> **Desktop shell:** GTK3 + WebKit2GTK  
> **Платформа:** Linux x86_64

---

## Зачем нужен этот проект?

Firefox предоставляет удобный интерфейс для управления закладками, однако Bookmark Library не является отдельным самостоятельным приложением. Чтобы редактировать закладки, обычно приходится сначала запускать Firefox.

Для простой операции — переместить, переименовать, удалить или добавить закладку — это означает запуск всего браузера и его компонентов.

**Bookmark Manager** создан для отделения этой части функциональности в небольшую самостоятельную программу.

В результате получается компактный portable Bookmark Manager, который можно использовать как отдельную utility-программу.

## Portable-режим

Приложение рассчитано на portable использование.

После распаковки структура примерно такая:

```text
Bookmark_Manager/
├── bookmarks
├── bookmarks.sh
├── index.html
├── icon.png
├── css/
│   └── style.css
├── js/
│   └── bookmarks.js
└── profiles/
    └── window_state.cfg
```

`bookmarks.sh` запускает программу с относительными путями.

Он задаёт:

```text
WEBKIT_USER_DATA_DIR
WEBKIT_CACHE_DIR
```

поэтому WebKit profile и cache находятся внутри каталога приложения.

Это позволяет копировать и переносить каталог приложения целиком.

### Важное уточнение

Portable означает переносимость **самого приложения и его данных**, но не означает, что системные Linux-библиотеки включены в архив.

Executable динамически использует библиотеки операционной системы. На целевой системе должны присутствовать совместимые GTK/WebKit зависимости.

## Как устроено приложение?

### 1. HTML/CSS/JavaScript

Интерфейс состоит из:

- `index.html`
- `css/style.css`
- `js/bookmarks.js`

Это обычный web-интерфейс.

Данные закладок сохраняются через:

```javascript
localStorage
```

WebView предоставляет среду выполнения этого web-кода внутри desktop-окна.

### 2. Native WebView launcher

Файл:

```text
bookmarks
```

— это native Linux executable, создающий окно и загружающий HTML-интерфейс в WebKit WebView.

Используются:

- GTK3
- WebKit2GTK 4.0
- JavaScriptCore GTK 4.0
- libsoup 2.4
- GLib и другие стандартные зависимости GTK/WebKit

Поэтому снаружи приложение выглядит как обычная Linux desktop программа, хотя UI реализован на HTML/CSS/JavaScript.

## WebView и совместимость Linux

Это наиболее важная часть при публикации готового бинарника.

Приложение **не содержит встроенный Chromium или Firefox runtime**.

Оно использует системный **WebKit2GTK**.

Поэтому WebKit2GTK является обязательной runtime-зависимостью.

Если библиотека отсутствует, программа не запустится. Например:

```text
error while loading shared libraries:
libwebkit2gtk-4.0.so.37:
cannot open shared object file
```

То же самое относится к другим native-библиотекам.

### Debian 12

Для конкретного release важно указывать реальную среду сборки.

Особенно важна совместимость **GLIBC**. Это системная библиотека, и её нельзя считать частью portable-приложения.

Проверка:

```bash
ldd ./bookmarks
```

и:

```bash
readelf --version-info ./bookmarks | grep GLIBC
```

В текущем бинарнике обнаруживается:

```text
GLIBC_2.38
```

Поэтому именно этот binary нельзя безоговорочно описывать как универсальный бинарник для Debian 12.

Если требуется поддержка Debian 12, рекомендуется собирать binary непосредственно в Debian 12 или в среде с совместимым более старым GLIBC baseline.

В конкретном executable используются, среди прочего:

```text

libgtk-3.so.0
libsoup-2.4.so.1
libglib-2.0.so.0

```

а также стандартные библиотеки графического стека.

Названия пакетов зависят от дистрибутива.

Для диагностики:


Если отображается:

```text

```

значит отсутствует соответствующая runtime-библиотека.

## Запуск

Сделайте launcher исполняемым:

```bash
chmod +x bookmarks.sh
```

Запуск:

```bash
./bookmarks.sh
```

Можно запускать и напрямую:

```bash
./bookmarks
```

Но рекомендуется использовать `bookmarks.sh`, поскольку он настраивает portable profile и cache.

## Где хранятся закладки?

WebKit использует browser storage.

В portable режиме launcher задаёт:

```text
WEBKIT_USER_DATA_DIR=<application>/profiles/user
WEBKIT_CACHE_DIR=<application>/profiles/user/cache
```

Таким образом, данные находятся рядом с приложением.

Это является частью portable-концепции.

Перед серьёзными изменениями рекомендуется использовать встроенный Export.

## Известные ограничения

### Linux runtime

Binary динамически связан с системными библиотеками.

Поэтому:

> **Portable ≠ полностью независимый от Linux системы.**

Сам каталог можно переносить, но совместимость GTK/WebKit/GLIBC на целевой системе должна быть проверена.

### Разные версии WebKit

Разные Linux-дистрибутивы могут предоставлять разные ABI и поколения WebKit2GTK.

Если необходимой ABI нет, готовый binary может не запуститься.

### Wayland / X11

GTK и WebKit используют графический backend системы.

Современные Linux-системы могут использовать Wayland, X11 или комбинацию обоих.

Фактическая совместимость зависит от GTK3, WebKit2GTK и установленных backend-библиотек.

## Диагностика

Если приложение не запускается:

```bash
ldd ./bookmarks
```

Ищите:

```text
not found
```

Проверка GLIBC:

```bash
readelf --version-info ./bookmarks | grep GLIBC
```

Проверка WebKit:

```bash
ldconfig -p | grep webkit2gtk
```

Проверка GTK:

```bash
ldconfig -p | grep libgtk-3
```
